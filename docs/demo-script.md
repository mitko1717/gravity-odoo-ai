# Демо-сценарій для Gravity (шпаргалка, ~20 хв)

Стенд: https://test6017.odoo.com · бот: https://t.me/gravity_test_promo_bot · репо: https://github.com/mitko1717/gravity-odoo-ai
Перед показом: `npm run bot` запущений; Telegram відкритий поруч; синтетичні дані (`*.demo@example.com`).
Головна думка: **правила рахують, AI пише чернетки, людина вирішує. Клієнтам нічого не йде автоматично.**

## Частина 1. Наскрізний шлях клієнта (етапи 1→9 карти)

| # | Що робиш | Де дивитись | Що сказати / «вау» |
|---|---|---|---|
| 1 | Залишаєш заявку на сайті (текст з бюджетом, площею, містом) | https://test6017.odoo.com/zayavka | Звичайна форма Odoo, без коду |
| 2 | Чекаєш ~30 с | Telegram: пуш «Новий лід» з AI-підсумком | Менеджер дізнається з телефону, а не коли відкриє CRM |
| 3 | Відкриваєш лід | CRM → лід → вкладка AI + чат (chatter) | AI витяг тип об'єкта, послуги, бюджет, пріоритет, відсутні дані, дублікати; текст клієнта = недовірені дані |
| 4 | У боті «Чернетка відповіді», потім «Створити пропозицію» | Telegram; Sales → Quotations | Пропозиція з шаблону за 1 натиск; ціни позначені «демо-ціна» |
| 5 | У боті «Підтвердити замовлення» | Sales → замовлення; Project → новий проєкт | Проєкт із шаблону: 9 задач, дедлайни, залежності |
| 6 | Invoicing: оплатити чернетку рахунку 30% | Invoicing → рахунок → Register Payment | Бот: «Передоплату отримано» → PM-активність |
| 7 | Проєкт → ⋮ → «AI: чернетка специфікації» | Задача «Проєктування», чат проєкту | AI підбирає лише з каталогу (product_id), невідоме відкидає |
| 8 | У боті «Погодити специфікацію» | Purchase → RFQs | Чернетки закупівель по постачальниках із погодженої специфікації |
| 9 | У боті «Підтвердити закупівлю» | Purchase | Без жодного відкриття Odoo |
| 10 | Проєкти (список) → ⚙ Actions → «Запланувати бригади» | Planning → Month → грудень | Чернетки змін для монтажників та інженера; повторний запуск не дублює |
| 11 | Задача «Тестування системи» → ⋮ → «AI: протокол пусконалагодження» | Вкладка Sub-tasks | 10 перевірок саме під встановлене обладнання |
| 12 | Закриваєш перевірки → стадія «Готово» → Save | Чат задачі; Telegram | Ворота: відкриті перевірки = «Здача заблокована»; усі закриті = «Тести пройдено» |
| 13 | Проєкт → ⋮ → «AI: лист клієнту при здачі» | Задача «Здача клієнту та навчання» → Description | Чернетка листа; PM перевіряє і надсилає сам |
| 14 | Sign → «Акт приймання (демо)» → Send | Sign → Documents | Підписання акта; документ позначений ДЕМО |

## Частина 2. Інші відділи (по 1 хв, вибірково)

| Відділ | Де | Що показати |
|---|---|---|
| Сервіс | Helpdesk → тікет «Запах гару від щитка» | AI: electrical/critical → Urgent, SLA 2 год; бот «Беру» |

| AI Hub | AI app → Agents → «Gravity: внутрішній асистент (демо)» | Питання «запах гару — що робити?»: відповідь з посиланням на регламент, без вигадок |
| Виробництво | Проєкт → ⋮ → «AI: звіт по об'єкту» | Статус і % рахують правила; AI лише текст, блокери з нотаток |

| Партнери | Contacts → партнер → ⋮ «Партнер: контакт відбувся» | Нагадування після 40/90 днів без контакту |
| Керівник | Telegram `/stats`, `/digest`, `/leads` | Воронка, кампанії, прострочення, сервіс — з телефону |

## Частина 3. Цифри та чесні межі
- Оцінка на 18 синтетичних заявках: `docs/eval-results.md` (виміряне ≠ прогноз для бізнесу).
- Межі: trial до ~19.11; бот локальний (Railway лише на період перевірки); AI-тексти фінансів іноді змішують мову — позначено як чернетку.
- Карта покриття 10 етапів + 4 допоміжних процесів: `docs/00-process-map-coverage.md`.

## Якщо щось не спрацювало
- Бот мовчить → перевір, що `npm run bot` працює; затримка до 30 с.
- Зміна стадії без ефекту → форма не збережена (☁️ біля назви) → Save.
- AI-дія без результату → F5; дивись запис «Action … executed» у чаті.
