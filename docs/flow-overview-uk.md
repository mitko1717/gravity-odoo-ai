# Gravity × Odoo × AI — огляд флоу (українською)

Неофіційний демо-стенд для тестового завдання, усі дані синтетичні.
Стенд: https://test6017.odoo.com · бот: https://t.me/gravity_test_promo_bot · репозиторій: https://github.com/mitko1717/gravity-odoo-ai · дашборд метрик: https://claude.ai/artifact/5xgb9wdaRM36gqQLHX2gT9

Перевірка всіх кроків одним тестом: `npm run regression` — запускає наскрізні сценарії через API Odoo по кожному етапу й пише підсумок у `tmp/regression-summary.md`.

**Принципи:** Odoo-first (нативні модулі й автоматизації, код лише там, де бракує). Правила рахують цифри й статуси, AI пише чернетки та витягує дані з тексту, людина вирішує. AI не пише в базу напряму: інструмент зі строгою JSON-схемою → перевірка в Python → запис. Текст клієнта, кандидата чи нотаток — недовірені дані (prompt injection перевірено). Клієнтам і постачальникам нічого не надсилається автоматично. Уся конфігурація — кодом (ідемпотентні `npm run seed:*`).

Як читати: **Що відбувається** → **AI / правила** → **Де в Odoo** → **У Telegram** → **Деталі**.

## 1. Маркетинг і партнери → нові звернення
- **Що відбувається:** клієнт залишає заявку на сайті; заявка одразу стає лідом у CRM. Маркетинговий звіт рахує вартість ліда й кваліфікованого ліда по кампаніях. Партнерам (дизайнерам, архітекторам) без контакту 40/90 днів створюється нагадування менеджеру.
- **AI / правила:** форма й лід — нативно; звіт: цифри — правила, висновки й рекомендації щодо бюджету — AI; нагадування партнерам — лише правила (AI тут не потрібен).
- **Де в Odoo:** [форма /zayavka](https://test6017.odoo.com/zayavka) · [CRM](https://test6017.odoo.com/odoo/crm) · [Knowledge → «Маркетинговий звіт»](https://test6017.odoo.com/odoo/knowledge) · [Contacts → «Партнер: контакт відбувся»](https://test6017.odoo.com/odoo/contacts)
- **У Telegram:** «🆕 Новий лід» з AI-розбором (ролі «Продажі»).
- **Деталі:** [02 — AI-аналіз заявок](02-lead-ai-analysis.md) · [12 — маркетинговий звіт](12-marketing-campaign-report.md) · [09 — нагадування партнерам](09-partner-contact-reminders.md)

## 2. Продажі → узгоджене рішення та вартість
- **Що відбувається:** AI розбирає заявку: тип клієнта, послуги, площа, місто, бюджет (грн/EUR → USD), строки, пріоритет-рекомендація, чого бракує, наступний крок, чернетка відповіді, перевірка дублікатів; призначає менеджера й активність. Менеджер створює пропозицію з шаблону (демо-ціни).
- **AI / правила:** розбір — AI зі схемою та валідацією; невідомі значення не вигадуються, а потрапляють у «бракує»; сумнівне → «Потребує перевірки». Пропозиція з шаблону — нативно.
- **Якість:** 18 синтетичних заявок — 18/18 тип і пріоритет, 15/15 послуги, 12/12 бюджет, дублікат і prompt injection оброблено, ~7 с на заявку → [eval-results](eval-results.md).
- **Де в Odoo:** [CRM](https://test6017.odoo.com/odoo/crm) → лід → вкладка «Gravity / AI» · [Sales](https://test6017.odoo.com/odoo/sales)
- **У Telegram:** «Взяти в роботу», «Чернетка відповіді», «📅 Консультація» (чернетка повідомлення з посиланням на запис + активність у ліді), «Створити пропозицію»; `/leads`, `/lead_ID`. Клієнт записався через сторінку запису Odoo (Appointments) → «📅 Клієнт записався на консультацію».
- **Деталі:** [02](02-lead-ai-analysis.md) · [03 — пропозиція → проєкт](03-sales-to-project.md)

## 3. Продажі та фінанси → підтверджене замовлення
- **Що відбувається:** підтвердження замовлення → чернетка рахунку на передоплату 30% + активність менеджеру «надіслати договір і рахунок»; договір — шаблон Sign «Договір (демо)». Оплату внесено → нотатка в проєкті й активність PM «запускати закупівлі».
- **AI / правила:** лише правила (суми й статуси мають бути точними).
- **Де в Odoo:** [Sales](https://test6017.odoo.com/odoo/sales) · [Invoicing → Invoices](https://test6017.odoo.com/odoo/action-account.action_move_out_invoice_type) · [Sign](https://test6017.odoo.com/odoo/sign)
- **У Telegram:** «Підтвердити замовлення»; «💬 Передоплату отримано» (PM).
- **Деталі:** [13 — договір і передоплата](13-contract-and-prepayment.md)

## 4. Інженери-проєктувальники → готовий проєкт
- **Що відбувається:** кнопка на проєкті складає AI-чернетку специфікації (обладнання й кількість) з каталогу під послуги й площу клієнта; інженер перевіряє й погоджує.
- **AI / правила:** AI обирає лише product_id з каталогу; невідомі позиції відкидаються й показуються; погодження — людина.
- **Де в Odoo:** [Project](https://test6017.odoo.com/odoo/project) → проєкт → ⋮ «AI: чернетка специфікації» → задача «Проєктування»
- **У Telegram:** «📐 AI-чернетка специфікації готова» → «Погодити специфікацію» (роль «Інженер»).
- **Деталі:** [14 — AI-специфікація](14-ai-draft-specification.md)

## 5. PM / виробництво → план реалізації
- **Що відбувається:** підтверджене замовлення створює проєкт із шаблону: 9 етапів із залежностями й дедлайнами. Прострочення → активність PM. Дія «Запланувати бригади» створює чернетки змін у Planning (ролі, ресурси, дати до дедлайну, перевірка накладок), PM публікує.
- **AI / правила:** правила (AI тут свідомо немає). AI-звіт по об’єкту: статус і % — правила, текст і блокери з нотаток — AI.
- **Де в Odoo:** [Project](https://test6017.odoo.com/odoo/project) · [Planning](https://test6017.odoo.com/odoo/planning) · проєкт → ⋮ «AI: звіт по об’єкту»
- **У Telegram:** `/projects`, `/project_ID` — 9 етапів, хто відповідає, кнопки; «⏰ Прострочено» → «+3 дні», «Готово».
- **Деталі:** [03](03-sales-to-project.md) · [15 — планування бригад](15-crew-planning.md) · [10 — звіт по об’єкту](10-site-status-report.md)

## 6. Комплектація / закупівлі → усе необхідне для робіт
- **Що відбувається:** погоджена специфікація → чернетки замовлень постачальникам (RFQ), згруповані по постачальнику; повторний запуск не дублює; позиції без постачальника показуються окремо.
- **AI / правила:** лише правила (групування детерміноване).
- **Де в Odoo:** [Purchase](https://test6017.odoo.com/odoo/purchase)
- **У Telegram:** «🛒 Чернетка закупівлі» → «Підтвердити закупівлю» (роль «Закупівлі»); постачальнику нічого не надсилається.
- **Деталі:** [08 — закупівлі зі специфікації](08-purchase-from-spec.md)

## 7. Монтажна команда → змонтована система
- **Що відбувається:** виїзди й монтаж — заплановані зміни в Planning (Field Service у Odoo 20 входить у Planning); прострочення ескалуються PM; звіт по об’єкту підсвічує ризики.
- **AI / правила:** правила + AI-текст у звіті.
- **Де в Odoo:** [Planning](https://test6017.odoo.com/odoo/planning) · [Project](https://test6017.odoo.com/odoo/project)
- **У Telegram:** етап «Монтаж» у `/project_ID`; після «Готово» наступний відповідальний отримує «👉 Ваша черга».
- **Деталі:** [15](15-crew-planning.md) · [10](10-site-status-report.md)

## 8. Інженери / налаштування → система працює правильно
- **Що відбувається:** на задачі «Тестування системи» AI складає протокол пусконалагодження (5–15 перевірок) під погоджене обладнання; інженер закриває кожну. Ворота: поки є відкриті перевірки, здача заблокована.
- **AI / правила:** чекліст — AI; ворота — правило.
- **Де в Odoo:** [усі задачі](https://test6017.odoo.com/odoo/action-project.action_view_all_task) → «Тестування системи» → ⋮ «AI: протокол пусконалагодження» → вкладка Sub-tasks
- **У Telegram:** `/project_ID` → 🧪 Чекліст (закриття з телефону); «⛔ Здача заблокована» або «💬 Тести пройдено» (PM).
- **Деталі:** [16 — пусконалагодження і здача](16-commissioning-and-handover.md)

## 9. PM / клієнт → об’єкт зданий
- **Що відбувається:** після воріт PM отримує задачу на здачу; AI готує чернетку листа клієнту (обладнання, пройдені перевірки, гарантія); акт приймання — шаблон Sign «Акт приймання (демо)». Надсилає людина.
- **AI / правила:** лист — AI, лише факти з системи; акт — нативний Sign.
- **Де в Odoo:** проєкт → ⋮ «AI: лист клієнту при здачі» → задача «Здача клієнту та навчання» · [Sign](https://test6017.odoo.com/odoo/sign)
- **У Telegram:** «💬 Тести пройдено: надіслати акт і лист».
- **Деталі:** [16](16-commissioning-and-handover.md)

## 10. Сервіс / підтримка → задоволений клієнт
- **Що відбувається:** звернення → тікет; AI визначає категорію й терміновість → нативний пріоритет і SLA (критичне — 2 год), призначення інженера.
- **AI / правила:** класифікація — AI (enum-и); SLA — нативно.
- **Де в Odoo:** [Helpdesk](https://test6017.odoo.com/odoo/helpdesk)
- **У Telegram:** «🚨 Критичний тікет» → «Беру» (роль «Сервіс»); якщо SLA прострочено — «🚨 SLA прострочено» керівнику проєктів (PM), ескалація; у /stats → Сервіс — % вчасно за 30 днів.
- **Деталі:** [04 — AI-тріаж тікетів](04-helpdesk-ai-triage.md)

## Telegram-бот: канал між відділами
Кожен етап має відповідального: вимоги й погодження специфікації — Продажі; виїзд, проєктування, налаштування, тестування — Інженер; закупівля — Закупівлі; монтаж і здача — PM. Етап → «Готово» (з бота або в Odoo) → наступний відповідальний отримує «👉 Ваша черга»; PM бачить усі зміни. Кожна дія з бота пишеться в Odoo й має посилання на запис. Доступ — whitelist + підтвердження адміністратора + ролі; кнопки теж перевіряють роль (етап — лише його відповідальний, PM і адмін — усе). → [BOT.md](../BOT.md) · [17](17-telegram-bot.md) · у боті `/flow`
